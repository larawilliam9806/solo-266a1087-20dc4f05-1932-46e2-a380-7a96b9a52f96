# 电量日核算（Flask + SQLite）

电网数据员上传晚到的电表累计读数与换表记录，系统按计量点把相邻读数连成区间，
自动算出可核算的逐日用电量，并标记换表造成的缺口区间。
电表隔几天才实抄一次时，结算员还可上传**估读（暂估读数）**拆分两次实抄之间的电量。

## 业务规则

### 实抄读数与换表

- **读数 CSV**（表头 `point,ts,value`）：计量点、UTC 时刻（ISO 8601，须带 `Z` 或 `+00:00`）、
  非负十进制千瓦时累计读数。
- **换表 CSV**（表头 `point,ts`）：计量点、UTC 换表时刻。
- **幂等**：同点同刻同值的原样重传自动跳过，不重复计数；
  同点同刻**不同值**（文件内或对比既有数据）→ 整批拒绝。
- **区间计量**：每个计量点按时刻连接相邻读数构成区间 `(t1, t2]`：
  - 区间内发生换表（`t1 < s <= t2`，**含后次读数时刻**）→ 标记缺口，不推算增量；
  - 否则增量 = 后次 − 前次，计入**后次读数所属 UTC 日**；
  - 增量为负（读数倒退）→ 整批拒绝。
- **晚到读数**插入后自动拆分旧区间，增量按新区间重新归属。
- **补录换表**后，原区间变为缺口，此前计入的增量自动撤销。

### 估读（暂估读数）

- **估读 CSV 沿用读数格式**（表头 `point,ts,value`），通过首页“上传估读”提交，
  单独存放在 `estimates` 表，每条记录带有**采纳状态**（已采纳/未采纳）与**未采纳原因**，
  可在首页预览或 `/estimates` 页按计量点查看。
- **同刻让位实抄**：同一时刻存在实抄时，该刻估读让位于实抄
  （未采纳原因 `superseded`）；即使两者数值不同也**不阻拦实抄**入库，估读原值保留。
- **分段整段采纳**：对两条**相邻实抄**之间的全部中间估读，仅当
  1. 该实抄区间按原口径判定**无换表**（不是缺口区间），且
  2. 两端实抄与全部中间估读按时刻排列后**单调不减**（插入全部中间估读后读数不倒退），

  才把这一段估读**一并采纳**；任一条件不满足，整段估读全部不采纳，
  原因分别记为 `swap`（含换表）或 `backwards`（倒退）。
- 落在首条实抄之前、末条实抄之后的估读没有两端实抄可校验，记为 `unbounded`，
  待后续补传实抄使分段成立后自动重核。
- **增量重核**：补传实抄、估读或换表时，只重核本批影响的实抄分段及同刻估读
  （新实抄拆分出的相邻分段、估读所在分段、换表落入的分段），
  估读状态与明细在**同一事务**内生效；任何校验失败整体回滚，保留原数据与原状态，
  被拒批次留有审计记录。
- 估读自身的同点同刻不同值冲突同样整批拒绝；同值重传幂等跳过。

### 两种用量口径

- **实抄口径（默认）**：用量页与 `/api/usage` 不带 `basis` 参数时只按实抄供数，
  结果与接入估读前完全一致。
- **暂估口径**：`/usage?basis=provisional`、`/api/usage?basis=provisional`
  把实抄读数与“已采纳”估读合并后连区间，仍沿用“增量计入后次读数所属 UTC 日”的归属规则；
  凡增量的任一端点是估读，该日标记 `estimated=true`（页面标注“含以估读为端点的增量”）。
- 未采纳估读不参与任何口径的计算。

### 事务与并发

- 一次上传的原始记录、估读状态与其影响的结果在同一事务内生效；
  任何校验失败整体回滚，保持旧数据与旧状态；被拒批次留有审计记录。
- SQLite WAL 模式；上传用 `BEGIN IMMEDIATE` 串行化，
  查询在单个读事务内完成，页面只能看到同一版本的完整结果（页面右上角显示数据版本号）。

## 运行

### Docker Compose（推荐）

```bash
docker compose up --build
```

访问 http://localhost:8000 。数据持久化在命名卷 `meter-data`（容器内 `/data/app.db`）。

### 本地开发

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt
python run.py                 # 默认 0.0.0.0:8000（waitress）
pytest tests/                 # 运行测试
```

环境变量：`APP_DATABASE`（SQLite 路径，默认 `./data/app.db`）、`PORT`（默认 8000）、
`SECRET_KEY`、`USE_WAITRESS=0` 可退回 Flask 内置服务器。

## 页面与接口

- `GET /` — 上传入口（实抄读数 / 估读 / 换表）、查询入口、估读状态预览、最近上传批次。
- `GET /estimates?point=..` — 已保存估读的采纳状态与未采纳原因（可按计量点筛选）。
- `POST /upload/readings`、`POST /upload/estimates`、`POST /upload/swaps`
  — 表单上传 CSV（字段名 `file`）；估读与读数同表头。
- `GET /usage?point=..&start=..&end=..&basis=actual|provisional`
  — 逐日用量表 + 缺口区间；日期缺省时取该点数据最近 31 天，`basis` 缺省为实抄。
- `GET /api/usage?point=..&start=..&end=..&basis=actual|provisional`
  — 同口径 JSON（含数据版本号，每日带 `gap` 与 `estimated` 标记），便于核对与集成。

## 实现说明

- 读数与估读均以文本存十进制（`Decimal` 计算），时刻规范化为定宽 UTC 字符串（字典序即时间序）。
- 日用量不做冗余物化：查询时在单事务内由原始记录现算，
  因此“原始记录/估读状态”和“受影响日结果”天然同事务生效，晚到数据的影响即时可见。
- 估读采纳状态是唯一随导入增量维护的派生数据：仅重核受影响实抄分段，
  随上传事务一起提交或回滚。
- 代码结构：`app/logic.py`（解析、校验、区间/日用量、估读采纳重核）、
  `app/routes.py`（页面与 API）、`app/db.py`（连接与建表）、
  `tests/test_app.py`（实抄/换表/并发测试）、`tests/test_estimates.py`（估读规则测试）。
